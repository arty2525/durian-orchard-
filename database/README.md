## สถานะ

สร้างฐานข้อมูล PostgreSQL จริงแล้ว ตาราง 10 ตารางเปิด RLS ครบ และมี view สรุปผลผลิตสำหรับลูกค้า
เว็บเดิมบน ChatGPT ยังไม่ได้สลับมาใช้ฐานข้อมูลนี้ ข้อมูลต้น ผล และรูปเดิมยังไม่ได้ย้ายเข้ามา
ไม่สร้างทะเบียนต้นปลอมหรือคาดเดาประวัติเดิม

## ตาราง

| ตาราง | หน้าที่ | การอ่านของลูกค้า |
|---|---|---|
| orchard_settings | ชื่อสวน พื้นที่ และจำนวนต้นเป้าหมาย | ได้ |
| trees | รหัสต้น พันธุ์ วัน/ปีปลูก ปีเริ่มให้ผล | ได้ |
| fruits | ต้นแม่ ฤดูกาล วันติดผล สถานะและน้ำหนัก | ได้ |
| seasons | จำนวนผลที่ไว้และเก็บเกี่ยวแต่ละปี | ได้ |
| photos | ข้อมูลอ้างอิงไฟล์ภาพ วันถ่าย คำอธิบาย | เฉพาะที่ published=true |
| care_events | น้ำ ปุ๋ย และการดูแล | ไม่ได้ |
| care_event_trees | รายชื่อต้นที่ได้รับการดูแลในเหตุการณ์นั้น | ไม่ได้ |
| internal_notes | บันทึกภายในของต้น/ผล/ฤดูกาล | ไม่ได้ |
| team_members | อีเมลและบทบาททีมงาน | เฉพาะแอดมิน |
| audit_log | ข้อมูลก่อน–หลังการแก้ไข | เฉพาะแอดมิน |

`public_season_summary` แยกจำนวนผลที่ไว้บนต้นออกจากจำนวนผลที่ลงทะเบียน
`orchard_private.tree_number_seq` ออกรหัส D0001 เป็นต้นไปอย่าง atomic และไม่ใช้เลขที่ถูกใช้แล้วซ้ำ
ปีในฐานข้อมูลเป็น ค.ศ. ส่วน UI แสดง พ.ศ. ได้

## สิทธิ์

ลูกค้าดูข้อมูลสาธารณะได้โดยไม่ต้องสมัครบัญชี
แอดมินและทีมงานของฐานข้อมูลใหม่นี้ใช้ Supabase Auth ซึ่งแยกจาก ChatGPT
สิทธิ์ตรวจจากอีเมลที่ยืนยันแล้วใน auth.users และ team_members ไม่เชื่อถือ user_metadata ที่ผู้ใช้แก้เองได้
เตรียมสิทธิ์แอดมินตามบัญชีที่เจ้าของสวนระบุไว้ในฐานข้อมูลแล้ว แต่ไม่ได้สร้างบัญชีหรือส่งอีเมลเชิญโดยอัตโนมัติ
เก็บ service_role/secret keys ไว้เฉพาะฝั่งเซิร์ฟเวอร์และห้าม commit

## ไฟล์และการทดสอบ

`schema.sql` เป็น reference schema สำหรับฐานข้อมูลใหม่ที่ว่าง ไม่ใช่ migration สำหรับรันทับฐานข้อมูลที่สร้างแล้ว
`verify.sql` เป็นการทดสอบใน transaction ที่ rollback ข้อมูลทดสอบและตัวตนทดสอบทั้งหมด
ทดสอบผ่าน: แอดมิน ทีมงาน ลูกค้า บุคคลนอกทีม การกันเลื่อนสิทธิ์ ภาพส่วนตัว บันทึกภายใน วันที่ ความสัมพันธ์ต้น–ผล รหัสอัตโนมัติ revision ประวัติแก้ไข และเพดานทีมงาน 5 คน

## ขั้นตอนเชื่อมเว็บต่อไป

1. ปรับ API/ตัวเชื่อมจาก D1 ไปเป็น Postgres/Supabase ตามโครงสร้างใหม่นี้
2. เพิ่มหน้า Supabase Auth และทดสอบอีเมล/การยืนยันตัวตนกับบัญชีจริง
3. สร้าง private Storage bucket `orchard-photos` ผ่าน Storage API และตั้งนโยบายไฟล์ให้ตรง published ของ photos (ตอนนี้มีเพียงตารางข้อมูลภาพ ยังไม่ได้สร้าง bucket หรือย้ายไฟล์)
4. ส่งออกข้อมูลจริงและรูปจากระบบเดิม แปลงและนำเข้า พร้อมเก็บรหัสต้นและ UUID ผลเดิม
5. ตั้ง sequence หลังนำเข้าข้อมูลให้สูงกว่ารหัสสูงสุด รวมรหัสที่ถูกลบในประวัติ
6. ทดสอบเว็บปลายทางและ QR เก่าก่อนสลับระบบจริง

ฐานข้อมูลนี้แยกจากเว็บเดิมแล้ว แต่ยังไม่ใช่การย้ายเว็บและไฟล์ภาพครบระบบ
